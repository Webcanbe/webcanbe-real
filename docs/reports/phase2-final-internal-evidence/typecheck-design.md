# Semantic TypeScript boundary review before implementation

The existing authenticated, PG-fenced, quota-accounted runner gains one fixed purpose: semantic-typescript-v1. It receives an immutable digest-bound data snapshot of source, a finite compiler-option object and declarations from the selected verified dedicated profile. It never receives platform credentials, a source checkout mount, arbitrary executable, plugin/config evaluator or network permission. A dedicated trusted TypeScript 5.9.3 bundle and standard library files are installed by the operator, separately from uploaded source. A worker-thread deadline bounds synchronous inference inside the existing Linux cgroup; termination and verified provider cleanup remain mandatory. No editor/host node_modules fallback resolves imported dependencies.

The compiler uses an in-memory CompilerHost; every read is confined to the captured source/declaration map plus the fixed trusted TypeScript libraries. User tsconfig plugins, executable configuration, package scripts, emit, watch and arbitrary filesystem operations are unavailable. Unsupported options/references produce explicit diagnostics rather than a fake semantic PASS. Diagnostics have a fixed count/message bound and are untrusted text. The response is rechecked against accepted revision, live project/session grants, generation/fence and the requested proposal digest. This operation is read-only and cannot accept source/history or alter an export. Existing parse, controlled compilation, independent build and runtime evidence remain separate labels. One admitted check per transport plus the existing global/tenant/project/host budgets prevents an unbounded compiler queue. Production secret, network, runner and source boundaries do not change.

Required evidence: semantic error after successful transpilation; correct cross-file React types; hostile plugin/config sentinel never executes; missing declarations fail explicitly; inference timeout and worker cleanup; stale/revoked/cross-tenant denial; same packaged HTTPS/PG/mTLS API; exact source/history/export preservation. Local TEST evidence does not certify deployed capacity.
