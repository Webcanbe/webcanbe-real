# Managed preview secret seam

Default: no provider, grants, values or delivery. An operator injects `ManagedPreviewSecrets` through `HostedEditor` using the production `ManagedSecretProvider` and `ManagedSecretPolicy` interfaces. Policy returns only server-owned references scoped to workspace/project, environment `preview`, explicit runtime `isolated-browser`, name and exact immutable version. A separate fresh owner-authority callback is mandatory. No browser API can grant values. Missing versions, rotation, revoked references/membership, provider errors and 1.5s provider deadlines fail closed; operations validate before and after, with a 1s idle revocation check. Rotation starts a fresh generation rather than changing a live execution silently.

Delivery is separate from source, history, compiler snapshots and artifact storage. Only the authenticated/fenced mTLS job message and private runner stdin carry values. The worker binds explicitly granted values as `globalThis.__WCB_PREVIEW_SECRETS__` in the isolated browser, never the platform browser. These values are intentionally readable/renderable by that project: confidential server credentials must not be granted to this runtime. General networking remains denied. Runtime logs are withheld for a managed-value generation, at both worker and controller, so encoding or splitting a value cannot bypass string redaction. Job errors return generic text. No values enter source exports. Up to 16 values, each 16–4096 UTF-8 bytes, are admitted.

Cleanup removes managed references from controller/worker memory and verifies existing whole-cgroup process/profile/IPC removal; JavaScript string zeroization is not claimed. Failed cleanup retains the existing quarantine/capacity fence. The local TEST implementation exercises the same interfaces with generated test values; cloud secret-manager provisioning, policies and rotation evidence remain external.
