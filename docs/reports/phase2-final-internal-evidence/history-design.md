# Bounded history compaction and restore

An explicit unchanged-source checkpoint moves the active transaction window into a lossless gzip archive inside the same canonical PostgreSQL history value. No separate object store or multi-system commit is introduced. The original active limits stay 1000 transactions, 1001 revisions and 64 MiB serialized history. Up to four archived windows are allowed; active plus archived uncompressed retention also remains 64 MiB. Compression therefore never evades the retained byte quota. Each archive has a SHA256 over canonical compressed bytes, a verified expansion length and project binding; decode is capped, and cached expansion metadata is rechecked. Archives remain immutable and append only.

PostgreSQL compares the fully expanded old ancestry with the proposed ancestry and requires an exact compaction of the previous active window, one new system checkpoint, and unchanged source bytes. Rejected receipts cannot alter archives. Existing file/journal/fsync recovery and PG source-epoch CAS still decide acceptance. Old transaction IDs, idempotency receipts, file before/after evidence, and safe selective inverses remain available through archive browsing and revert.

Restore reconstructs the requested accepted revision by checking and reversing complete later file evidence, then verifies its source digest. A read-only preview identifies all affected files and hashes. Acceptance recompiles the complete proposed project and records a new, undoable source transaction against the reviewed current head. Stale heads, missing evidence, source-scope digest mismatch, archive corruption, revocation and the ordinary 100-file mutation limit fail closed. No history rewrite or hidden project snapshot becomes canonical. Backup/PITR storage, operator retention, and deployed disaster recovery remain external evidence.
