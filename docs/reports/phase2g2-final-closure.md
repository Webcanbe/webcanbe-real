## Composed authority and commit domain

`scripts/hosted/editor-main.ts` is the tested explicit startup. It loads trusted operator configuration and constructs the verified PostgreSQL pool and actual asynchronous `HostedEditor`; the default local Vite plugin remains a separate developer mode. The hosted process imports shared modules but constructs no SQLite registry, source authority or scheduler. Every asynchronous registry/session/artifact result is awaited. IDs in requests are references; identity comes from the authenticated cookie and provisioned issuer/subject mapping, followed by fresh workspace/project membership and same-login project capability.

`withHostedSource` materializes an authorized PG revision into a private disposable directory so existing synchronous source parsers and mutation code can operate on real files. `DurableSource` staging skips SQLite. The staged source and existing ledger are accepted by one PostgreSQL CAS transaction before the HTTP response can report success; a final epoch/revision/authority read prevents mixed-state output. Compiler-owned directories retain stable paths for incremental compilation but are repopulated from PG every use, cannot commit and are removed on close. Durable drafts are per-user proposals with separate CAS; they are never a second canonical source/history system.

Preview allocation reads an immutable PG artifact and uses the real PG lease store directly with the hosted mTLS provider. Both controller and gateway enforce ownership/epoch/generation/deadline around commands and results. HTTP acceptance exercises two real signed logins, separate workspaces/projects, owner/editor/viewer, cross-tenant references, source/history/export/diagnostics/artifact denial, stale generation, controller fencing, lease expiry, stop/restart, allocation exhaustion, delayed sample after membership change and lost cleanup acknowledgement. The independent recovery loop handles expired quarantined jobs even when no new editor request arrives.

Source/history fault injection uses actual PG triggers. The HTTP child is actually SIGKILLed while a source transaction is sleeping; its disconnected request has no success, the orphaned sleeping DB backend is explicitly terminated, and a fresh editor reads exact prior source/history. This tests a real process crash plus explicit database cancellation, not every storage-server outage. An actual artifact INSERT failure prevents preview success without changing accepted source. Artifact and runner cleanup run independently; uncertain cleanup retains quarantine and capacity.

## Authoring and refresh improvements

- Missing responsive overrides now append real CSS media declarations or known Tailwind variants from an unambiguous existing origin, with explicit source scope and normal inverse/history validation. No free-coordinate canvas model, arbitrary selectors/media strings or guessed instance authority is introduced.
- Save-all submits every dirty file in one accepted transaction. Acknowledged drafts survive process restart and browser reload; CAS detects competing backups. Unacknowledged keystrokes can still be lost before the 250ms backup completes, and stale/conflicting backups require review. - Bounded Unicode text and fixed navigation/edit keys travel through the trusted raster viewer and parent frame/generation validation to isolated Playwright keyboard input. Real API tests type Korean/CJK text; real built-editor viewer tests type ordered text. Clipboard/native IME/accessibility/streaming/long-session completeness is not claimed.
- React18/19 component-only Code and Visual updates preserve counter state through accepted PG revisions. CSS updates preserve state; entry-module changes reload and reset component state; structural file changes restart generation. These classifications are asserted separately. Unsupported graphs, hooks/signatures, CSS Modules and arbitrary Vite/plugin HMR are not generalized into a PASS.
- Async preview sweep now rechecks observations after awaits so an old revision observation cannot retire a newer completed commit/update. Worker reload logs are cleared before loading the new document, preserving new startup diagnostics. UI raster responses are guarded by connection epoch, generation and revision; queued input drains through the current session callback. Refresh attempts also pin revisions and reject superseded completions. A deterministic built-browser test holds an old capture request until after Code acceptance/refresh, receives a real409 and proves the new preview remains ready with working input. Independent follow-up review covered these response-ordering fixes. Compiler admission now checks and records its pending reservation atomically after awaited expiry; eight simultaneous requests admit one materialization.
