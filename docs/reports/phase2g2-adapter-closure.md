## Implementation and integration boundary

The source files remain canonical. No canvas schema, arbitrary uploaded Node execution, public hosted mode, provider account or cloud resource was added.

- **Identity:** `OidcIdentityProvider` verifies server-configured HTTPS token/JWKS endpoints, RS256/ES256 signature, issuer/audience/azp/expiry/issued-at/nonce, authorization-code PKCE and one-use browser-bound login state. It ignores access/refresh tokens. Account linkage uses provisioned issuer+subject, never email or client IDs. `HostedLoginBoundary` can be mounted before the engine API; its CSRF bootstrap/logout use exact HTTPS Host/Origin and host-only Secure/HttpOnly cookies. PostgreSQL and local SQLite state adapters exist. PostgreSQL identity mapping and session issuance share one transaction/lock; disabled-user tombstones block reissue. Local signed TEST issuer/TLS tests are not production identity evidence.
- **Durable storage:** `PostgresProjectStore` commits real file bytes and the existing revision ledger together. Full-key authorization, source/revision/epoch CAS, immutable old history, exact retry, rejected-draft receipt append, quota, rollback and tombstoned deletion are enforced. `withHostedSource` uses a fresh private disposable source checkout for the existing synchronous parser/mutation/compiler code, accepts back into PG, and refuses mixed-epoch results. `PostgresArtifactStore` binds immutable payloads to workspace/project/revision/generation/digest, verifies hashes, serializes project delete/put and preserves revoke tombstones. No bucket name or guessed digest is authority.
- **Execution:** `HostedLinuxRunnerProvider` uses HTTPS/mTLS to a fixed-command Linux gateway. Both controller and gateway consult the same PostgreSQL fence around commands/results. `LinuxHostRunnerProvider` invokes the same root-owned launch/stop policy as Lima: separate namespaces/cgroup, native Chromium sandbox, no source mount, cleared project environment, zero external network, bounded RPC/input/output and fixed resources. The gateway's credentials/config remain outside its job runtime mount. LocalLimaRunnerProvider and its security policy remain available unchanged. No Docker socket, arbitrary command or uploaded configuration is introduced.
- **Distributed ownership:** PG clock/row locks, controller UUID, monotonic epoch, owner tuple, request hash, idempotency key, immutable generation, worker host, lease/deadline, heartbeat, stop state and quarantine are durable. Controller A was actually SIGKILLed while owning an isolated job; B waited for expiry, incremented the epoch, verified old-job cleanup and recovered capacity. A's old heartbeat/result was refused. A live controller cannot be displaced. Unknown/live-generation cleanup cannot return verified success. This is a real database/two-process test against one local VM, not a two-cloud-host outage drill.
- **Resources:** admitted jobs retain 1,536 MiB memory, no swap, 150% CPU, 192 tasks, a 60-second application deadline and a 65-second external cgroup backstop. Default PG admission is global4/workspace2/project2/host2; reserved/quarantined jobs consume capacity. Failed cleanup does not free a slot. A concrete deployment still needs sizing, periodic recovery, backups/PITR/retention and monitoring.
- **History hardening:** history is capped at 64 MiB and 1,000 transactions/1,001 revisions; journal cap is 160 MiB. Over-limit writes fail before the journal/canonical source changes, and oversized disk history is rejected before parsing. No history is silently compacted/deleted; operator archival/migration and durable unsaved drafts remain open.
- **Safe compatibility fixes:** .mts/.cts intake now matches the existing static Vite grammar. Profile selection uses React/ReactDOM/Vite core requirements before reporting other unsupported packages. No package/lock/config admission check was relaxed to make a corpus project pass.

**Critical remaining implementation gate:** the new PostgreSQL stores/session boundary are asynchronous. The existing editor `ProjectRegistry`/`HostedSessionBoundary`/`ProjectPersistence`/`ArtifactStore` path is still synchronous and local. Do not pass async methods into those interfaces, layer the SQLite scheduler over the PG provider and call it hosted, or treat the gateway process as the full application. The existing editor/source/Canvas/history/preview API needs a coherent async adapter composition and end-to-end two-user tests. The provider deployment package is reproducible; the hosted editor application is not complete. This is internal implementation work, not a missing credential.
